# Developer overview

Continuum is a Cargo workspace plus a pnpm workspace.

## Crate layout

```
crates/
├── continuum-core/      orchestration runtime — senses, triage, orchestrator, workers, memory, voice, health
├── continuum-mcp/       MCP server exposing Windows capabilities to Claude Code
├── continuum-llm/       llama.cpp wrapper for local LLM inference
└── continuum-vision/    ONNX Runtime wrapper for local vision models
apps/
├── desktop/         Tauri 2 + Next.js 15 dashboard
└── docs/            Nextra docs site (this site)
```

## Where to start contributing

- **Bundled skills** (`skills/`) — lowest-effort, highest-visibility change.
- **MCP tools** (`crates/continuum-mcp/src/tools/`) — add new capabilities.
- **Dashboard** (`apps/desktop/src/`) — polish, new tabs, new views.
- **Perception** (`crates/continuum-core/src/senses/`) — the hardware-close code.
- **Self-healing** (`crates/continuum-core/src/health/`) — more checks, better repair recipes.

## Key invariants

1. **Data flows up, commands flow down.** Senses → triage → orchestrator → workers. A worker never triggers the orchestrator; the orchestrator never touches the senses directly.
2. **Local models are optional.** If a model is missing, the degraded mode must still work. See [graceful degradation in KNOWN_ISSUES.md](https://github.com/vixco/Continuum/blob/main/KNOWN_ISSUES.md).
3. **`continuum.exe` is release-only** on the runtime path. `llama-cpp-sys-2` + debug + Windows = crash in `ucrtbased`. See [CLAUDE.md build workflow](https://github.com/vixco/Continuum/blob/main/CLAUDE.md#build-workflow).
4. **MCP tool surface is stable.** Tools can be added, but tool signatures can't change without a version bump — downstream Claude Code sessions rely on them.

## Tests

```bash
cargo test --workspace
cargo test -p continuum-core                    # single crate
cargo test -p continuum-core -- triage          # matching "triage"
```

UI tests: none yet. The dashboard relies on type-level correctness + manual QA.

## Benchmarks

- `cargo run --release --bin continuum-triage-bench` — triage accuracy + latency
- `cargo run --release --example voice_latency_bench -p continuum-core` — voice pipeline latency
