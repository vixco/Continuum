# Dashboard

The Tauri 2 + Next.js desktop dashboard is where you inspect, configure, and manage Kairo. Eight tabs, all live-updating.

## Home

Live perception frame, current triage decision, active workers, cost-so-far today, and a recent-actions ring. This is the tab you'll have open most of the time.

## Brain

The four-layer diagram with the current model loaded in each slot. Click any layer to swap models, tweak intervals, or run a "Test" pass. Useful for calibrating triage thresholds without editing TOML.

## Memory

Three sub-views: **Episodic** (vector search across past events), **Semantic** (key-value facts with full CRUD), **Raw log** (every perception frame, with filter and pagination). A "Wipe memory" button at the bottom — requires typing `WIPE`.

## Tools

Lists MCP tools and bundled + user skills. Toggle skills on/off. Install a skill from a Git URL. Create or edit a skill inline (Markdown editor with a live preview of the frontmatter).

## Voice

Wake word on/off, sensitivity slider, voice picker with preview, language selector, microphone + speaker dropdowns with test buttons, volume slider, hotkey editor, ambient-mute toggle.

## Automations

One-shot and recurring scheduled tasks. Each row shows the schedule, the next run, enabled state, and a run-now button.

## Logs

A live-updating log stream from the 10 000-entry ring buffer. Filters by level, layer, component, text, and timestamp. Click any entry to expand its structured fields.

## Health

All registered components with their current status (OK / degrading / error / unknown). A prominent "Fix Issues" button spawns the repair agent — its streaming output renders live in a side panel.

Also exposes: backup status, last successful repair, rolling 24 h error rate per component, "Run backup now" and "Rollback config" actions.

## The two processes

The dashboard process and the runtime process are separate. They communicate via:

- `~/.kairo/state.json` — the runtime writes a snapshot every 2 s; the dashboard reads it
- `~/.kairo/repair-intents/` — the repair agent writes intents; the runtime acts on them
- Tauri `emit`/`listen` events for state / logs / repair bridging

State can lag by up to 2 s after a config change. See [dashboard.md](https://github.com/PrincNL/kairo-ai/blob/main/docs/dashboard.md) for the full architecture.
