# Self-healing

Continuum is pre-alpha software. Things break. The **repair agent** is a dedicated Claude Code session with access to Continuum's installation, its logs, and a set of narrow repair tools.

## What it can do

- Read the generated repair context
- Start an offline Continuum runtime after a verified backup, then wait for a fresh state heartbeat
- Run a lightweight component self-test (`mcp__continuum__repair_test_component`)
- Report explicit manual next steps in the streamed output if it cannot fix the issue

## What it cannot do

- Run shell commands or edit files
- Reinstall models or roll back configuration from the safe Health-tab session
- Claim that queued restart or escalation intents were executed; this release has no runtime consumer for them
- Push changes to GitHub — it has no network write tools
- Wake more workers or spawn itself recursively
- Delete episodic / semantic memory

## How to trigger a repair

- **From the dashboard:** Health tab → "Fix Issues" → review the live one-time preview → "Run safe repair". If the runtime is offline, the desktop takes a backup, starts it once, and waits for a fresh heartbeat up to the configured bounded timeout (90 seconds by default). Other issues are diagnosed and escalated without pretending a restart occurred.
- **By voice:** say "continuum, something isn't right" (triage recognises this via `execute_simple`).
- **From the CLI:** `continuum repair` (coming soon — see [ROADMAP.md](https://github.com/vixco/Continuum/blob/main/ROADMAP.md)).

## Nightly diagnostics

Every night at 04:00 Continuum runs a self-diagnose pass:

1. Ping each component's health check
2. Roll up 24-hour error rates
3. Warn in the Health tab if any component's error rate exceeds 5%
4. Take a manifest-verified, versioned config snapshot into `~/.continuum-backups/YYYY-MM-DD/`

## Backups

Nightly zips at `~/.continuum-backups/YYYY-MM-DD/` contain:

- `config.toml`
- `automations.json`
- `permissions.toml`
- `semantic.sqlite`
- `orchestrator-system.md`

Retention defaults to the 7 most recent archives and is configurable. Every repair run and every mutating repair tool call creates and verifies a new archive first. Rollback validates the selected archive and TOML, creates another safety backup, and swaps `config.toml` reversibly.

## What to do if the repair agent can't help

1. Read the logs directly at `~/.continuum/logs/` — they're structured JSON, timestamped, per component.
2. Open an issue with the bug-report template.
3. The agent's final output always ends with either `RESOLVED`, `ESCALATED`, or `PARTIAL`. If `ESCALATED`, attach the streaming transcript to your issue — it's already a great bug report.
