# Skills

A skill is a `SKILL.md` file that tells the orchestrator how to handle a specific workflow. The orchestrator picks them up automatically at wake time based on trigger matching.

## Bundled skills

Kairo ships five starter skills in `skills/`:

- **`daily-briefing`** — spoken morning briefing from memory + overnight worker activity
- **`code-review`** — structured review of a diff, PR, or file
- **`project-context`** — loads project-specific facts + recent episodic history
- **`email-draft`** — concise reply / new-message drafts matched to recipient tone
- **`file-organizer`** — plan-then-apply folder tidying, never deletes

## Anatomy of a skill

```markdown
---
name: code-review
description: Review a diff / PR / file for bugs, style, and design issues
triggers:
  - "review this"
  - "what do you think of this code"
  - "code review"
source: bundled
---

# Code review

When this skill is active, the orchestrator should:

1. Identify the diff or file to review (from the user's message, clipboard, or active window).
2. Read it using `fs_read_file` if needed.
3. Analyse for: bugs, unsafe patterns, style, design, test coverage.
4. Report back as a bulleted list grouped by severity.
5. Do NOT apply fixes unless the user explicitly asks.
```

The frontmatter `triggers` list is substring-matched against the wake text, the foreground app, the recent audio transcript, and a set of tags. A skill with a trigger of `"review this"` fires when the wake text contains "review this".

## Writing your own

Create `skills/<name>/SKILL.md` in the Kairo repo root (for development) or in `~/.kairo/skills/<name>/SKILL.md` (for user-scoped skills). Kairo scans both locations at startup.

Good skills have:
- A short, specific `description` — this is what the triage layer reads to decide when to suggest the skill.
- A narrow scope — one workflow, not ten.
- A clear output format so the orchestrator's response is easy to summarise.
- Explicit refusal rules (what to do if the task is out of scope).

## Installing a skill from a URL

Dashboard → Tools tab → "Install from URL" → paste a Git URL. Kairo runs `git clone --depth 1` into a temp directory, validates the `SKILL.md`, and moves it into `~/.kairo/skills/`.

## Disabling a skill

Dashboard → Tools tab → toggle the skill off. Disabled skills are listed at `skills.disabled` in the config and are not loaded into the orchestrator's prompt, even if their triggers match.

## Skill budget

The orchestrator prompt has a per-wake token budget for skill content (`skills.token_budget`, default 2000). If multiple skills match, Kairo ranks by trigger score and takes the top few until the budget is full. Forced skills (passed explicitly at wake time) bypass the budget.

## Hot reload

If `skills.hot_reload = true` (default), Kairo watches the `skills/` directory for changes and reloads skills on the fly. Parse errors surface in the Tools tab so you can see them while editing.

Note: the file watcher only watches the repo-root `skills/` today. User skills in `~/.kairo/skills/` are loaded at startup but not auto-reloaded. Restart Kairo after editing a user skill.
