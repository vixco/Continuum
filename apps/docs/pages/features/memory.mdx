# Memory

Kairo has three memory stores. You own all of them. They all live under `~/.kairo/memory/`.

## Raw log (SQLite)

Every perception frame is written to `raw_log.sqlite`. This is the firehose: screenshots, audio transcripts, context, salience. Nightly rotation keeps `storage.retention_days` worth (default 30).

You can browse the raw log from **Memory tab → Raw log**. You can `DELETE` rows directly — Kairo doesn't fight you.

## Episodic memory (LanceDB vector store)

Every `remember` decision, wake event, and tool call goes through the episodic distiller (runs every 15 minutes, configurable at `memory.distillation_*`). The distiller writes vectorised events to a LanceDB table under `~/.kairo/memory/episodic/`, using fastembed's BGE-small-en-v1.5 (384-dim, 66 MB, local).

When the orchestrator wakes, Kairo vector-searches episodic memory against the wake text and retrieves the top-K events as context.

You can:
- Browse episodic events in **Memory tab → Episodic**
- Full-text search across them
- Delete individual events
- Export the whole table (copy the LanceDB directory — it's self-describing Arrow files)

## Semantic memory (SQLite key-value + graph)

Stable facts about you: `user.name`, `user.timezone`, `project.kairo.dir`, `preference.language`. Structured as a key-value store with optional graph edges for things like "this project is owned by this person".

Reserved prefixes:
- `system.*` — written only by Kairo itself
- `kairo.*` — version, install date, etc.

Everything else is writable from the orchestrator via `memory_set_fact` (with confidence clamping: inferred ≤0.7, observed ≤0.8, user_stated ≤0.9) or directly from the dashboard.

## Privacy

- **Never leaves your machine** unless the orchestrator is called — and only the top-K retrieved events go into the wake context, never the whole store.
- **Encrypted at rest?** No. The file system protects the data via your OS user account. If you want disk-level encryption, use BitLocker.
- **Audit trail:** every memory write includes the source (`inferred` / `observed` / `user_stated` / `tool_call`) and a timestamp.

## Wipe

Dashboard → Memory tab → Wipe memory. Requires typing `WIPE` to confirm. Deletes the raw log, episodic table, and semantic DB. Your configs, logs, and models are untouched.

## First-run seeding

On a fresh install, Kairo seeds five semantic facts automatically so the orchestrator has a sensible baseline:

- `user.timezone` — from the system
- `user.language` — from the OS locale
- `user.os` — e.g. "Windows 11"
- `kairo.version` — e.g. `0.1.0-alpha.1`
- `kairo.install_date` — ISO-8601 timestamp

You can edit or delete these at any time.
