# Permissions

Continuum enforces tool permissions in the native MCP process **before a tool
body runs**. The model prompt is not the security boundary.

## Tool tiers

| Tier | Behavior |
|---|---|
| `auto` | Runs without a confirmation. Use only for low-risk, read-only tools. |
| `session-approved` | Opens one native approval per MCP process/session, then remembers that approval for the same tool. |
| `always-confirm` | Opens a native approval for every call. |
| `blocked` | Cannot run through the ordinary MCP process. |

Unknown tools fail closed as `always-confirm` until they are classified in
`config/default-permissions.toml`.

Bundled defaults are compiled into the desktop and MCP binary. User overrides
are written atomically to:

```text
<data-dir>/permissions.toml
```

The Tools page reads the effective policy and persists dropdown changes to that
file. A newly spawned MCP process uses the updated policy on the next agent run.

## Important defaults

- Ordinary context and allowlisted filesystem reads are `auto`.
- Direct vault search/get requires session approval; sensitive notes are still
  withheld by the egress gate after approval.
- Clipboard reads, memory wipes, permanent vault deletes and worker spawns use
  `always-confirm`.
- Repair mutations remain `blocked` outside the dedicated, short-lived Health
  capability flow.

## Filesystem allowlist

Filesystem reads must remain inside one of the canonicalized roots Continuum
knows about. A hardcoded deny list applies even inside an allowed root:

- credential directories such as `.ssh`, `.aws`, `.gnupg` and browser profiles;
- private-key and keystore files;
- `.env` variants;
- large generated trees such as `node_modules` and `target`.

Symlinks are canonicalized before the root and deny-list checks.

## Native approvals

Approvals are shown outside the model transcript and default to **Deny**.
Headless sessions cannot satisfy an approval and fail closed. Approval summaries
minimize message bodies, credentials and other payload-bearing fields before
showing them.

## Cloud-egress boundary

Permission to read locally is not automatically permission to send content to a
cloud model. Continuum applies a second egress gate to MCP results:

- vault notes marked `sensitive` are withheld;
- sensitive rows are removed from vault search results;
- secret-looking response fields are redacted;
- audit events for memory, filesystem, clipboard, worker and web tools are
  stored as `local_only` and carry minimized argument shapes rather than full
  bodies, prompts, paths or URL queries.

## Agent OS

Agent OS uses an additional capability policy for computer and connected-app
actions. Public mutations must run inside `agent_run_plan` with a stable
`run_id` and typed postcondition. Destructive connected-app actions default to
deny, and an unknown dispatched mutation is never replayed automatically.
