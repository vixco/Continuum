# Models

All model config lives at `~/.continuum/config/default-models.toml`. Edit it directly or use the dashboard Brain tab.

## Vision

```toml
[vision]
name = "SmolVLM-256M"
model_path = ""                # blank = search ~/.continuum/models/vision
gpu_enabled = false            # auto-detected at runtime; explicit true forces ONNX-GPU
input_width = 384
input_height = 384
```

To swap: drop a new ONNX vision model into `~/.continuum/models/vision/` and point `model_path` at it. The model must implement the `VisionModel` trait — see `crates/continuum-vision` for the interface.

## Triage

```toml
[triage]
model_path = "~/.continuum/models/triage/qwen3-8b-q4_k_m.gguf"
gpu_layers = 999               # max; 0 for CPU-only
grammar_path = "prompts/triage-grammar.gbnf"
max_retries = 3
```

Any GGUF model that supports grammar-constrained generation works. The triage prompt (`prompts/triage-system.md`) is tuned for Qwen 3; switching to a different family may need prompt tweaks.

## Orchestrator

```toml
[orchestrator]
model = "claude-opus-4-6"      # or "claude-sonnet-4-6"
max_context_tokens = 4000
claude_binary = ""             # blank = search PATH
mcp_config_path = ""           # auto-generated per wake
```

## Workers

```toml
[workers]
mode = "auto"                  # "auto" | "budget" | "power"
budget_model = "claude-sonnet-4-6"
power_model = "claude-opus-4-6"
max_concurrent = 3
default_timeout_secs = 1800
```

## STT and TTS

```toml
[audio]
whisper_model_path = "~/.continuum/models/stt/whisper-medium.bin"
whisper_language = "auto"      # or "en", "nl", etc.

[tts]
engine = "piper"
primary = "en"
voices = { en = "en_US-norman-medium" }
```

## GPU detection

At startup Continuum probes for NVIDIA CUDA in two steps: it tries to load
`nvcuda.dll` (so a driver install without `nvidia-smi` on PATH still
registers as CUDA-capable) and runs `nvidia-smi --query-gpu=memory.total` to
read VRAM. When CUDA is present **and** VRAM is at least `resources.gpu_min_vram_mb`
(default 3000 MB, enough for Qwen3-8B Q4_K_M with headroom), the triage LLM
fully offloads to GPU (`gpu_layers = 999`) and the vision model builds its
ONNX Runtime sessions with `CUDAExecutionProvider` (falling back to CPU +
a warning if the CUDA EP commit fails). Below the VRAM floor, or on a box
without CUDA, both fall back to CPU.

This is part of the adaptive resource policy (`[resources]` in config /
the dashboard Settings → Resources panel). To force CPU-only for debugging
regardless of detected hardware, set:

```toml
[resources]
gpu_enabled = false
```

To force GPU on even when detection fails, set `gpu_enabled = true`. Leave
it unset (`null`) for the auto-detect behaviour above.

## Where models live

Default search order:

1. Explicit `model_path` in config
2. `$CONTINUUM_MODELS_DIR` (set by the installer)
3. `~/.continuum/models/`
4. `~/.continuum-dev/models/` (for developer builds)
