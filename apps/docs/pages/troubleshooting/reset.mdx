# Resetting Kairo

Sometimes the cleanest fix is a fresh start. Here's how, from least to most destructive.

## 1. Restart the runtime

Right-click tray → Quit. Relaunch from the Start Menu. This clears in-memory state without touching anything on disk.

## 2. Rollback the config to last night's snapshot

Dashboard → Health tab → pick a backup date → "Rollback config". Nightly backups live in `~/.kairo-backups/`. Rolls `config.toml` only.

## 3. Reset the config to defaults

```powershell
Remove-Item $env:USERPROFILE\.kairo\config\default-models.toml
Copy-Item <repo>\config\default-models.toml $env:USERPROFILE\.kairo\config\
```

Relaunch Kairo. Memory, logs, and models are untouched.

## 4. Wipe memory

Dashboard → Memory tab → "Wipe memory" → type `WIPE`. Deletes:

- Raw log SQLite
- Episodic LanceDB table
- Semantic SQLite

Configs, models, logs, and backups are kept.

## 5. Reinstall models

```powershell
Remove-Item -Recurse $env:USERPROFILE\.kairo\models
scripts\download-models.ps1
```

~6.5 GB of downloads. Use when models seem corrupted or you want to pick up a newer revision.

## 6. Reinstall Kairo entirely (but keep data)

```powershell
Remove-Item -Recurse $env:LOCALAPPDATA\Kairo
irm https://raw.githubusercontent.com/PrincNL/kairo-ai/main/scripts/install.ps1 | iex
```

User data at `~/.kairo/` is preserved because we never delete it without explicit instruction.

## 7. Full factory reset

```powershell
Remove-Item -Recurse -Force $env:LOCALAPPDATA\Kairo
Remove-Item -Recurse -Force $env:USERPROFILE\.kairo
Remove-Item -Recurse -Force $env:USERPROFILE\.kairo-backups
irm https://raw.githubusercontent.com/PrincNL/kairo-ai/main/scripts/install.ps1 | iex
```

Relaunch, the onboarding wizard runs again.

## If even that didn't help

Open an issue with the bug-report template. Include:

- The exact commands you ran
- The last 50 lines of `orchestrator.log` / `voice.log` / whichever component failed
- `kairo --version`
- `claude --version`
- The output of `kairo setup` if it runs
